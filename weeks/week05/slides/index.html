Part 1

XML Describes Custom Data

XML defines tag sets for data, documents, configuration, feeds, SVG, and enterprise systems.

HTML vs XML

Same Angle Brackets, Different Purpose

HTML

Known elements such as h1, p, and nav describe web page structure.

XML

You define meaningful tags such as course, title, and hours.

Course catalog

Small XML Dataset

XMLcatalog.xml
<?xml version="1.0" encoding="UTF-8"?>
<courses>
  <course id="CS0135">
    <title>Web Programming and Design</title>
    <hours>3</hours>
    <active>true</active>
  </course>
</courses>

Syntax labels

XML Parts

Declaration

<?xml version="1.0"?>

Root

<courses>

Element

<title>...</title>

Attribute

id="CS0135"

Well-formed XML

Rules the Parser Requires

  • Exactly one root element.
  • Opening and closing tags match.
  • Elements are properly nested.
  • Names are case-sensitive.
  • Attribute values are quoted.
  • Empty elements may use <tag />.

Common errors

Find the XML Problems

XMLbroken
<courses>
  <course id=CS0135>
    <title>Web Programming</name>
    <hours>3</hours>
  </course>
</catalog>
Reveal

Attribute value needs quotes, title closes as name, and root closes as catalog.

Elements or attributes?

Modeling Choice

Attribute

Best for IDs, categories, or small metadata: id="CS0135".

Element

Best for content that may grow or need structure: <title>.

Entities and CDATA

Reserved Characters

XMLtext safety
<note>Use &lt;strong&gt; in HTML examples.</note>
<example><![CDATA[if (score > 90) { pass(); }]]></example>

Entities encode reserved characters. CDATA preserves text that should not be parsed as XML markup.

Namespaces

Avoid Naming Collisions

XMLprefixes
<catalog xmlns:web="https://example.edu/web" xmlns:book="https://example.edu/books">
  <web:title>Portfolio Website</web:title>
  <book:title>HTML Reference</book:title>
</catalog>

Well-formed vs valid

Two Quality Levels

Well-formed

Follows XML syntax rules.

Valid

Also follows a declared schema such as XSD.

Schemas

XSD in One Minute

An XML Schema Definition can state which elements are allowed, where they appear, and what data types they contain. DTDs are older historical context; XSD is the modern concept to recognize.

Tiny schema idea

Simple XSD Shape

XSDconceptual
<xsd:element name="hours" type="xsd:integer" />
<xsd:element name="active" type="xsd:boolean" />

You do not need to memorize long schema documents this week.

Browser display

Raw XML Is Developer-Facing

Browsers usually show XML as a collapsible tree or plain structured text because custom tags have no built-in visual meaning.

Styling and transforms

CSS and XSLT Overview

CSS for XML

Can display custom elements, but this is mostly a demonstration technique.

XSLT

Transforms XML into another format such as HTML using template rules.

Processors

DOM Versus SAX

DOM

Builds a tree in memory. Easier to navigate, heavier for huge files.

SAX

Reads as events. Efficient for large streams, harder for random access.

Enterprise context

SOAP and WSDL

SOAP and WSDL are XML-based web service technologies still seen in enterprise systems. Modern beginner web APIs more commonly use JSON.

Part 2

JSON Represents Data for Modern Web APIs

JSON is compact, strict, and easy for JavaScript applications to read.

Same data

Course Catalog as JSON

JSONcatalog.json
{
  "courses": [
    {
      "id": "CS0135",
      "title": "Web Programming and Design",
      "hours": 3,
      "active": true
    }
  ]
}

JSON parts

Objects, Arrays, Values

Object

{ "key": value }

Array

[ item, item ]

String

"text"

Other values

Numbers, booleans, null.

Valid JSON

Strict Syntax Rules

  • Keys must use double quotes.
  • String values must use double quotes.
  • No comments in standard JSON.
  • No trailing commas.
  • Objects and arrays must close correctly.

Common JSON errors

Fix This Object

JSONbroken
{
  id: "CS0135",
  "title": "Web Programming",
  "hours": 3,
}
Reveal

Quote id and remove the trailing comma after 3.

JSON vs JavaScript object

They Look Similar, Not Identical

JSON

Data text format. Double-quoted keys and strings.

Object literal

JavaScript syntax. Can allow unquoted keys and expressions.

Side by side

XML Versus JSON

XML

Verbose, supports attributes, namespaces, document workflows, and schemas.

JSON

Compact, maps naturally to JavaScript, common for APIs and AJAX.
